# 16.08 - Calidad Asistencial y Auditoría Clínica (PDCA)

> 📸 **Imagen requerida:** Ciclo PDCA completo con ejemplos TES; flujo de notificación Sensafety; matriz de indicadores de calidad.

> [!abstract] Objetivo
> > Entender los sistemas de mejora continua (PDCA), auditoría clínica y notificación de incidentes (Sensafety) para elevar la calidad asistencial, aplicando indicadores objetivos y corrección sistémica de errores.

---

## 1. Fundamentos del Sistema de Calidad

### 1.1. Ciclo PDCA (Plan-Do-Check-Act)

| Fase | Nombre | Acción en TES | Herramienta | Indicador de éxito |
|------|--------|---------------|------------|-------------------|
| **P - Plan** | Planificar | Identificar problema y objetivos | Mapa de procesos | Definición clara del problema |
| **D - Do** | Hacer | Implementar cambio | Piloto en turno | Implementación sin interrupciones |
| **C - Check** | Verificar | Medir resultados | Dashboard | Mejora ≥15% en KPI |
| **A - Act** | Actuar | Estandarizar o ajustar | Protocolo actualizado | Eliminación o reducción del problema |

### 1.2. Principios de calidad aplicados al TES

- **Enfoque al paciente:** La calidad se mide por resultados asistenciales, no solo por cumplimiento.
- **Liderazgo:** La dirección del servicio impulsa la cultura de calidad.
- **Participación del personal:** El TES es agente activo de mejora.
- **Enfoque basado en evidencia:** Decisiones fundamentadas en datos.
- **Comunicación:** Información clara entre niveles asistenciales.
- **Mejora continua:** Calidad como proceso no como estado.

### 1.3. Sistema de gestión de calidad en emergencias (ISO 9001/TZDS adaptado)

```
POLÍTICA DE CALIDAD
  ├── Objetivos SMART
  ├── Procedimientos documentados
  ├── Formación del personal
  ├── Seguimiento y medición (KPIs)
  ├── Auditoría interna
  ├── Revisión por dirección
  └── Mejora continua (PDCA)
```

## 2. Ciclo PDCA (Mejora Continua) - Aplicación Detallada

### 2.1. Fases del ciclo (con plantilla TES)

```
PLAN (Planificar)
  ├── Definir el problema concreto: Tiempo de respuesta elevado en dolor torácico
  ├── Establecer objetivo SMART: Reducir tiempo respuesta <15 min en 80% de casos
  ├── Identificar causas raíz: Rutas ineficientes, falta de priorización
  └── Diseñar intervención: Nuevo protocolo de dispatch + GPS inteligente

DO (Ejecutar)
  ├── Implementar protocolo piloto en 1 base durante 30 días
  ├── Registrar cada uso y tiempo obtenido
  ├── Capacitar al personal en nueva metodología
  └── Mantener documentación de pruebas

CHECK (Verificar)
  ├── Recopilar datos: 30 casos con tiempo medio 14.1 min
  ├── Comparar con objetivo: 80% cumplen <15 min
  ├── Analizar desviaciones: 4 casos >15 min por saturación
  └── Preparar reporte con resultados y desviaciones

ACT (Actuar)
  ├── Estandarizar protocolo piloto como oficial
  ├── Publicar en manual de operaciones
  ├── Capacitar a todas las bases en 4 semanas
  └── Programar revisión en 3 meses
```

### 2.2. Aplicación en emergencias

- **Problema:** Tiempo de respuesta superior al objetivo.
- **Plan:** Rediseñar ruta y asignación de recursos.
- **Do:** Ejecutar nueva ruta durante 1 mes.
- **Check:** Medir tiempos y satisfacción.
- **Act:** Estandarizar la nueva ruta o ajustar según desviaciones.

### 2.3. Plantilla de reporte PDCA

```
REPORTE PDCA - [Nombre del proyecto]
1. Problema identificado:
2. Objetivo planteado:
3. Causas raíz analizadas:
4. Intervenciones implementadas:
5. Resultados obtenidos (KPI %):
6. Desviaciones detectadas:
7. Decisiones adoptadas:
8. Próximos pasos:
Firma responsable: _________________ Fecha: ___/___/___
```

## 3. Auditoría Clínica

### 3.1. Objetivo y alcance

- **Evaluar cumplimiento** de protocolos y guías clínicas.
- **Identificar desviaciones** entre práctica real y estándar.
- **Proponer mejoras** basadas en datos, no en opiniones.

### 3.2. Metodología (con tabla de técnicas)

| Técnica | Descripción | Aplicación en TES | Herramienta |
|---------|-------------|-------------------|-------------|
| **Revisión de historias** | Auditoría retrospectiva de casos | Revisar 20 casos de IAM mes anterior | Checklist de auditoría |
| **Observación directa** | Evaluar actuación en tiempo real | Observar triaje y técnicas de RCP | Grabadora + checklist |
| **Encuestas de satisfacción** | Pacientes y familiares | Valorar trato y información recibida | Formulario estandarizado |
| **Indicadores clave** | Métricas estandarizadas | Tiempo respuesta, cumplimiento checklist | Dashboard |

### 3.3. Tipos de auditoría

| Tipo | Alcance | Frecuencia | Resultado |
|------|---------|------------|-----------|
| **Interna** | Equipo revisa sus propios casos | Mensual | Mejora continua |
| **Externa** | Organismo independiente evalúa el servicio | Trimestral | Certificación de calidad |
| **Por pares** | Profesionales del mismo nivel evalúan entre sí | Bimensual | Feedback formativo |
| **Clínica** | Enfocada en resultados del paciente | Trimestral | Mejora asistencial |

### 3.4. Checklist de auditoría clínica TES

| Ítem | Sí/No | Observaciones |
|------|-------|---------------|
| Se documenta hoja de asistencia completa | | |
| Se aplican protocolos de SVB/SVA correctamente | | |
| Se comunica al receptor con modelo MIST | | |
| Se registró tiempo de respuesta | | |
| Se usó correctamente medicación | | |
| Se documentaron DNR/LET si procede | | |
| Se notificó incidente en Sensafety | | |
| Se realizó debriefing post-evento | | |

## 4. Notificación de Incidentes (Sensafety)

### 4.1. ¿Qué notificar? (con clasificación)

| Categoría | Ejemplos | Ruta |
|-----------|----------|------|
| **Error de medicación** | Dosis incorrecta, vía errónea, omisión | Sensafety inmediato |
| **Equipo defectuoso** | Desfibrilador sin batería, monitor fallando | Reporte técnico + Sensafety |
| **Fallo en comunicación** | Pérdida de contacto, entrega incompleta | Sensafety + parte de traslado |
| **Incidente de tráfico** | Accidente con ambulancia, maniobra riesgosa | Notificación a dirección + Sensafety |
| **Evento adverso** | Lesión por técnica, extravasación, neumotórax | Sensafety + documento clínico |
| **Casi error** | Situación que pudo terminar en daño | Sensafety (anónimo posible) |

### 4.2. Formulario de notificación (con detalle)

| Campo | Contenido | Guía de relleno |
|-------|-----------|-----------------|
| **Datos del evento** | Fecha, hora, lugar, profesionales implicados | HH:MM exactos, DNI de todos |
| **Descripción** | Qué pasó, secuencia cronológica | Narrativa objetiva, sin juicios |
| **Causa inmediata** | Error humano, fallo de equipo, comunicación | Identificar fábrica de error |
| **Causa raíz** | Por qué existía la condición del fallo | Análisis 5 porqués |
| **Medidas correctivas** | Acciones tomadas para no repetirlo | Acción concreta + responsable + fecha |
| **Responsable** | Persona que coordina la mejora | Supervisor de turno o calidad |

### 4.3. Anonimato y protección

- **Protección del profesional:** Notificar no implica sanción automática.
- **Cultura sin culpa:** Enfocada en sistema, no en persona.
- **Confidencialidad:** Datos protegidos según RGPD.
- **Investigación de causas:** Análisis sistemático, no individual.
- **Mejora colectiva:** Compartir aprendizajes sin identificar autores.

## 5. Errores Comunes

### 5.1. Errores de sistema

| Error | Causa | Medida de sistemática |
|-------|-------|----------------------|
| **No notificar** | Miedo, cultura de culpa | Política de protección y anonimato |
| **Culpar al profesional** | Cultura punitiva | Enfoque sistémico, revisión de procesos |
| **Notificar tarde** | Olvido o falta de tiempo | Formulario accesible en dispositivos móviles |
| **No documentar** | Falta de cultura | Incluir en hoja de asistencia y protocolo |

### 5.2. Errores humanos vs. fallos de sistema (con matriz)

- **Error humano:** Acción no intencionada sin fallo previo.
- **Violación:** Acción consciente contra norma.
- **Fallo de sistema:** Condición que permite el error.
- **Enfoque:** Siempre buscar la causa sistémica, no solo la humana.

## 6. Mejora de la Calidad

### 6.1. Checklists

| Lista | Aplicación | Ejemplo |
|-------|------------|---------|
| **Lista de verificación pre-salida** | Vehículo y equipo | ¿Desfibrilador cargado? ¿Oxígeno suficiente? |
| **Checklist de RCP** | Calidad de compresiones | Frecuencia, profundidad, desfibrilación |
| **Checklist de traslado** | Seguridad y documentación | Fijación, monitorización, entrega |
| **Checklist de limpieza** | Equipo y ambulancia | Desinfección, reposición de material |

### 6.2. Simulacros

- **Frecuencia:** Trimestral o semestral según servicio.
- **Objetivo:** Practicar protocolos sin riesgo real.
- **Evaluación:** Métricas de tiempo, técnica y trabajo en equipo.
- **Feedback:** Sesión posterior con puntos fuertes y débiles.

### 6.3. Formación continua

- **Actualización de protocolos:** Revisión anual obligatoria.
- **Talleres prácticos:** Habilidades técnicas y blandas.
- **Acreditaciones:** Mantener competencias vigentes.

## 7. Indicadores de Calidad

### 7.1. Indicadores clave (KPI TES)

| Indicador | Objetivo | Medición | Frecuencia |
|-----------|----------|----------|------------|
| **Tiempo de respuesta** | < 15 min en código rojo | Registro de salida y llegada | Diaria |
| **Calidad de RCP** | Compresiones profundas y a ritmo | Desfibrilador con feedback | Por paciente |
| **Cumplimiento de checklist** | > 95% de ítems completados | Auditoría mensual | Mensual |
| **Satisfacción del paciente** | > 85% satisfecho | Encuesta al alta | Trimestral |
| **Notificación de incidentes** | 100% de eventos registrados | Sistema Sensafety | Continuo |
| **Hoja de asistencia completa** | > 95% de casos | Auditoría retrospectiva | Mensual |
| **Documentación de DNR/LET** | 100% de documentos registrados | Auditoría de casos | Mensual |
| **Debriefing post-evento** | > 80% de eventos críticos | Registro Sensafety | Mensual |

### 7.2. Indicadores de seguridad (con tabla detallada)

| Indicador | Meta | Revisión | Herramienta |
|-----------|------|----------|-------------|
| **Error de medicación** | Cero errores graves | Mensual | Notificación Sensafety |
| **Accidente de tráfico** | Cero accidentes con lesiones | Trimestral | Reporte de circulación |
| **Caídas durante traslado** | Cero caídas evitables | Mensual | Incidentes documentados |
| **Infección asociada** | Cero por falta de antisepsia | Continuo | Auditoría de limpieza |

## 8. Caso Práctico

> [!example]
> **Escenario:** En una guardia, olvidas conectar el monitor de ECG durante 3 minutos en un paciente con dolor torácico. El paciente es trasladado al hospital, donde sufre una reacción adversa.
>
> **Paso 1:** Notificar el incidente en Sensafety de forma anónima o protegida.
> **Paso 2:** Participar en el análisis de causas raíces del equipo.
> **Paso 3:** Proponer medida correctiva: checklist de "medicación administrada" como paso obligatorio entre actuación y traslado.
> **Paso 4:** Implementar la medida y medir cumplimiento durante 1 mes.
> **Paso 5:** Estandarizar doble-check en protocolo de despedida de paciente.
> **Paso 6:** Documentar todo en hoja de calidad y compartir aprendizaje con el equipo.
>
> **Ampliación - Análisis de causas raíz (5 porqués):**
> - ¿Por qué se olvidó conectar el monitor? → Por distracción durante la vía.
> - ¿Por qué la distracción? → No hay checklist previo de conexión.
> - ¿Por qué no hay checklist? → No se estandarizó el protocolo.
> - ¿Por qué no está estandarizado? → No hubo auditoría de calidad reciente.
> - ¿Por qué no se auditó? → Falta de tiempo asignado para calidad.
> - **Solución:** Implementar checklist 5P (Preparación, Paciencia, Protocolo, Prueba, Paso final).

## 9. Errores Críticos

| Error | Consecuencia | Solución |
|-------|--------------|----------|
| **No notificar incidentes** | Repetición del error | Cultura sin culpa; proteger al notificador |
| **Culpar al profesional** | Ocultación de fallos | Enfoque sistémico, no personal |
| **No medir resultados** | Mejora sin evidencia | Indicadores objetivos y periódicos |
| **Simulacros sin feedback** | Sin aprendizaje real | Debriefing estructurado tras cada simulacro |
| **Ignorar casi errores** | Pérdida de oportunidad de mejora | Notificar también eventos sin daño |
| **No usar checklist** | Errores sistémicos | Checklist obligatoria con verificación |
| **No documentar en hoja** | Inviabilidad de auditoría | Registrar siempre evento y actuación |
| **No actuar sobre auditoría** | Pérdida de confianza en calidad | Cierre del ciclo PDCA con medidas |

---

## 10. Puntos Clave

- La calidad es un **viaje continuo**, no un destino.
- El **PDCA** es el método estructurado para mejora.
- Los **incidentes** son oportunidades, no fracasos.
- La **cultura sin culpa** aumenta la seguridad del paciente.
- El **debriefing** y la **formación** cierran el ciclo de mejora.
- Los **KPIs deben ser medibles, objetivos y accionables**.
- La calidad asistencial incluye **seguridad del paciente y del profesional**.
- La **auditoría clínica** detecta brechas entre protocolo y práctica real.
- La **notificación anónima** fomenta cultura de transparencia.
- El **cierre del ciclo PDCA** asegura que las mejoras se institucionalizan.
